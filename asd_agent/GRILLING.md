## Q1 这个需求是谁的

需求文档说"干预领域信息过载、家长不知道下一步做什么" —— 这是结论，不是证据。

要准备的：

- [ ] 访谈过几个家长？他们现在实际怎么做的？
- [ ] 拿到报告之后，家长手里其实已经有一张"建议清单" —— 他们缺的到底是
      执行力、场地、耐心，还是别的？
- [ ] 一个具体用户故事：某个妈妈，拿到 XX 报告，之前试过什么，卡在哪一步，
      这套东西替她解决了哪一步。

> **建议口径**：如果确实没做过用户访谈，就承认，改成"我自己/我朋友就是 ASD 家庭，
> 我观察到的具体卡点"。面试官可以接受"我就是目标用户"，不能接受"我猜的"。
>
> **加分补充**（见 sources.md 第 0 节）：国家卫健委《孤独症谱系障碍儿童干预康复指南
> （2026年版）》把家庭干预列为基本原则和独立干预内容。需求不是猜的，是有政策锚点的。

## Q2 它和一个会说话的 ChatGPT 有什么区别

每一步（解析分数、生成计划、根据反馈调整）如果都贴进对话框，
Claude/GPT 加一段好 prompt 是不是就做完了？

要准备的：

- [ ] 一句话说清"为什么这不是一个 prompt"
- [ ] 连续多轮的对话里，画像/进度怎么保持？
- [ ] 连续性测试：同一画像跑两次，产出差异多大？

> **建议押注两处**：
> 1. **状态** —— 每个能力域有跨对话存在的持久化阶段（未开始→入门→练习中→已掌握→泛化），
>    可审计。聊天窗口做不到。
> 2. **约束** —— 每天 30 分钟、家里现有物品、单人可执行，是硬约束求解。
>    LLM 自由生成不保证满足，需要检索 + 打分 + 校验的管道。
>
> **最强答案**："我做过 prompt-only 版本，它在连续性和约束满足上都不达标，所以才拆管道。"

## Q3 这三个 Agent 的边界是真的吗

规划 / 教练 / 评估，三个听起来像三个 prompt。

要准备的：

- [ ] 每个 Agent 的输入输出数据结构（JSON schema）是什么？
- [ ] Agent 之间传的是自然语言还是结构化状态？
- [ ] 评估 Agent 判断"该不该升级难度"，依据是什么？为什么它比规划 Agent 更懂进度？
- [ ] 为什么规划和评估不合并？

> **建议**：MVP 阶段承认可能只有 1.5 个真 Agent —— 规划 + 教练合并，
> 评估先做成**纯规则阈值函数**（"同一活动连续 3 天执行率>80% 且家长报告有进步 → 升级"）。
>
> **规则能做的别用 LLM 做** —— 这本身是加分的设计决策。
> 三者间传 JSON 而非自然语言，才叫多智能体；schema 变更如何兼容也要讲。

## Q5 "长期记忆"具体是什么

"记住上周练了什么、哪些活动抗拒、哪些进展明显" —— 这是把对话历史塞进 context 吗？

要准备的：

- [ ] 存在哪？（文件 / DB）
- [ ] 结构长什么样？
- [ ] 怎么检索 —— 每次全量注入，还是按能力域/时间取子集？
- [ ] 用户 3 个月后才回来，第一次注入的是什么？
- [ ] 记忆写错了怎么办（家长报"做了"其实是没做）？
- [ ] 有写入条件吗？什么信息才允许进长期记忆？

> **建议**：设计成**两层** ——
> **① 结构化档案**（每个能力域当前状态、偏好、禁忌、家长背景）：每次都注入；
> **② 事件流**（每次执行的 activity_id、结果、抗拒程度、备注）：可检索历史，
> 用来回答"最近 7 天练了什么""下周该换什么"。
>
> 明确说：**记忆不是对话历史**，有 schema、有写入条件、有更新/遗忘策略。
> 这一层最能体现工程思维，务必讲透。

## Q6 怎么证明这东西有用

当前指标："家长执行率" + "能力域状态变化"。

问题：执行率是家长自报的，可以刷；状态变化是自己的规则改的，自证循环。

要准备的：

- [ ] 怎么知道是系统的功劳，不是自然恢复？
- [ ] 对照组在哪？
- [ ] 没有严格评估，你的"反馈闭环"是不是自我感动？

> **建议降维到可辩护的三条，都能跑脚本出数字，面试现场展示比嘴说强**：
> 1. **可复现性** —— 同一画像喂 10 次，周计划的一致性 / 多样性
> 2. **约束满足率** —— 生成的计划有多少条真的满足"≤30分钟 / 只用常见物品 / 单人可执行"，
>    用规则脚本自动检查，给百分比
> 3. **安全底线** —— 会不会生成明确不推荐的做法？用一张禁止清单做自动校验
>
> **并主动说**：demo 级别无法做临床验证，我评估的是工程属性，不是疗效
> （见 sources.md 第 6 节）。
