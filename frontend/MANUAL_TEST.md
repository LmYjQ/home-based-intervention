# 前端手动测试脚本（PostgreSQL 迁移后）

**照着点，每一步都写了「输入什么 → 预期看到什么」。预期不对就是回归，记下来。**

生成于 2026-10-19，迁移到 PostgreSQL 之后。后端已实测全通
（13 条路由、180 并发请求 0 失败），本脚本覆盖**只有浏览器里才能验**的部分。

## 第 0 步：起环境（不是测试，是前提）

### 0.1 起 PG（带 volume，重启不丢数据）

```bash
docker run -d --rm --name ganyu_pg \
  -e POSTGRES_PASSWORD=postgres -e POSTGRES_DB=ganyu \
  -p 127.0.0.1:55432:5432 \
  -v ganyu_pgdata:/var/lib/postgresql/data \
  81bd698b4594
```

**预期**：`docker ps` 里 `ganyu_pg` 状态 `Up`。
端口必须绑 `127.0.0.1`，写成 `0.0.0.0` 会把开发库暴露到局域网。

已存在同名容器时先 `docker stop ganyu_pg` 再起（`--rm` 会连带删掉旧容器，
但 **volume 里的数据留着**，这正是加 volume 的目的）。

### 0.2 起后端

⚠️ **本机 8000 端口被别的程序占着**（实测：一个 python 进程，HTTP 404）。
所以后端走 **8123**，并且必须改 vite 代理（见 0.3）。

```bash
cd /Users/qiyusama/Documents/code/ganyu
ASD_DB_PATH=/tmp/ganyu_dev.db ASD_NO_LLM=1 \
PYTHONPATH=.:./asd_agent \
./.venv/bin/python -c "import uvicorn,server; uvicorn.run(server.app,host='127.0.0.1',port=8123,log_level='warning')"
```

**预期**：
```bash
curl -s http://127.0.0.1:8123/api/health
```
→ `{"ok":true,"no_llm":true,"mode":"live"}`

**`ASD_NO_LLM=1` 必须加** —— 否则每出一张卡片要等 30-45s（7B 两次串行调用），
手测会以为卡死了。想测真实模型路径时再去掉它。

### 0.3 改 vite 代理端口（一次性）

`frontend/vite.config.js` 里代理写死 `target: 'http://127.0.0.1:8000'`。
本机 8000 被占，不改的话**前端会打到别人的服务上，全是 404**。

把该行改成：
```js
'/api': { target: 'http://127.0.0.1:8123', changeOrigin: true },
```

### 0.4 起前端

```bash
cd frontend && npm run dev
```

**预期**：`Local: http://localhost:5173/`。
⚠️ 5173 被占时会自动退到 **5174** —— **以启动日志里的端口为准**，别用错。

浏览器打开后按 F12 打开 Console，**整个测试过程 Console 必须没有红色报错**。

## 第 1 步：建档（含红旗）

**输入**：页面最上方应该是「建档：评估报告 → 能力画像」表单，
`评估报告原文` 框里**已经有默认样本**，包含这句：

> 行为方面：他去**咬自己的袖子**，需要提醒，情绪激动时会用手推人。

**操作**：月龄保持 `34`，直接点「**开始建档**」。

**预期**（离线模式下约 1 秒）：
1. 进度条**逐条**吐出，至少两行：
   `离线模式：用确定性降级画像（可信度 0.1…）` → `回指校验完成，未通过 0 条；写库`
   —— 必须是**两条不同的真实文本**，不是假进度条。
2. 出现红旗列表，含 **`urgent` / `self_injury`**（对应「咬自己的袖子」）。
3. 可信度显示 **0.10**，旁边橙色字：`低于升级闸门 0.5，状态机将冻结全部升级（这是正确行为）`。

> ⚠️ **0.10 是正确输出，不是 bug。** 空库只能降级，
> 真实报告要 18-47s（真调模型）才会有高可信度。

**失败长什么样**：红旗为空 → 红旗规则没接上；进度只有一行 → SSE 没逐条推。

## 第 1.5 步：★ 画像本体看得见

**输入**：无需操作 —— 建档完成后页面顶部应出现「**能力画像**」卡片。

**预期**：
- 标题右侧：`共 10 条 · 报告明说 N 条 · 模型推断 M 条`
- 下面按**能区分组**列出（**中文能区名**：大运动 / 精细动作 / 语言 / 认知 / 社会适应），
  优先能区带蓝色「优先」标签
- 每行五列：技能名 · `L0`~`L5` · 置信度 · 来源 · **证据引文**
- 底部有个可展开的「家长约束」

> ⚠️ **离线建档时证据引文全是空的、来源全是「推断」、置信度 0.10** ——
> 这是正确的：降级路径不编证据。要看到有引文的真实效果，
> 得跑一次真实模型建档（18-47s），或者看下面这段命令写进去的示例画像：
> ```bash
> cd asd_agent && ../.venv/bin/python -c "
> import store
> from capabilities import AbilityProfile, SkillAssessment, ParentConstraints
> store.save_profile(store.connect('/tmp/ganyu_dev.db'), AbilityProfile(
>   child_id='demo-001', child_age_months=34, report_date='2026-09-20',
>   assessments=[
>     SkillAssessment(domain='gross_motor', skill_item='独走稳', level=3,
>       evidence_quote='能独立走平路，但上下楼梯需要扶', source='report_stated', confidence=0.85),
>     SkillAssessment(domain='social_adapt', skill_item='共同注意', level=1,
>       evidence_quote='', source='inferred', confidence=0.35)],
>   priority_domains=['gross_motor','social_adapt'],
>   parent_constraints=ParentConstraints(daily_minutes_available=30,
>     materials_at_home=['杯子','绘本','小汽车','积木'], alone_only=True,
>     avoid_load_sensory=True), overall_confidence=0.72))"
> ```
> 刷新页面后应看到「独走稳 L3 conf=0.85 **报告明说**」带引文，
> 以及「共同注意 L1 conf=0.35 **推断**」（橙色低置信）无引文。

**为什么单列一步**：`/api/state` 原先只给 `levels`（技能名→等级），
画像的证据引文和来源全在 DB 里却没有出口；而 `ProfileForm` 里那份明细
在建档完成后被 `v-if` 卸载了 —— 家长建完档反而看不到建了什么。

**失败长什么样**：看不到「能力画像」卡片 → `/api/state` 没给 assessments（前端 v-if 条件不对）。

## 第 2 步：今天的安排

**输入**：无 —— 切到「**今天**」标签页即可（进页面自动取，命中缓存是毫秒级）。

**预期**：
- 顶部一行：`N 条 · 共 X 分钟 / 预算 Y 分钟`。**X 应接近 Y 但不超过 Y**
  （30 分钟预算实测排 28-29 分钟，因为备料时间也算在家长的时间里）。
- 下面是 **N 张活动卡片**，每张含：`为什么推它`、`为什么今天给他做这个`、
  步骤、**提示阶梯**、`★ 如果他不配合`（退路）、`怎么算成功`。
- 每张卡片底部**自带一行反馈**（活动名、判据、四个结果按钮、步数）。
- 如果之前生成过，标题右侧会有 `（已生成过，直接读）`。

### ★ 2.1 生成一次，不要每次都重跑

**操作**：把标签切到「进度」再切回「今天」，**连做 5 次**。

**预期**：
- 每次都显示 `（已生成过，直接读）`，
  进度里能看到 `YYYY-MM-DD 已经生成过（N 条），直接读`。
- **没有任何一次**出现 `检索候选…` 开头的进度行 ——
  出现就说明又重跑了（真跑要 30-45s）。
- 后端耗时 **<10ms**（进度行里的 `t=` 数字）。

**失败长什么样**：每次切回来都看到「检索候选」→ 缓存没生效。

### ★ 2.2 「重新生成」按钮

**操作**：点「**重新生成**」。

**预期**：进度里重新出现 `检索候选…` + `装箱：N 条，共 X 分钟（预算 Y）`。

### 2.3 换日期 / 重新建档会自动重排

**操作**（任一）：
- 把顶部日期改成**别的日期**，或
- 切到「建档」点「**重新建档**」，再回到「今天」

**预期**：
- 换日期 → 那一天是空的（没生成过），点「生成今天的安排」才排。
  **不会**把上一天那份原样搬过来。
- 重新建档 → 旧安排**自动作废重排**，
  进度里会出现 `画像已更新，之前排的那份作废 → 重新排`。

**为什么这条重要**：只按日期缓存的话，家长把 30 分钟改成 15 分钟，
看到的还是按 30 分钟排的旧计划，而界面上没有任何地方提示它是旧的。

## 第 3 步：★ 逐条反馈 —— 本 demo 最重要的一步

**这是阶段 4b 的核心，也是最容易验错的地方。**

### 3.1 每张卡片自带一行反馈

**操作**：无需操作 —— 当天每条活动下面**自动**有一行反馈。

> 早先要先去「候选」页点「**用它**」把活动一条条加进来，
> 而那一页现在**已经删掉了**：一次就把当天装箱满，
> 家长看到的就是当天该做的全部，不需要再自己挑。
> （还需要挑，说明系统没把「今天该做什么」做完。）

**预期**：反馈行数 = 活动卡片数，每行的活动 id 与它**上面那张卡片**一致。

#### ★ 逐行核对：每行的判据必须是**它自己**的

**这是本脚本最容易漏的一条**，曾经真的错过：
多行曾经**全都显示同一活动的判据**，
家长会照着那条的标准去判断另外几条做没做到。

**逐行看这三处，每行都必须是该行自己的**：

| 位置 | 该显示什么 |
|---|---|
| 反馈行的活动名 | 与上方卡片标题一致 |
| `判断标准：…` | 该活动**自己**的成功判据 |
| `做到几步：____ / N` | 该活动**自己**的步骤数（**各条应不相同**） |

实测 3 条活动的判据各不相同、步数为 `4 / 3 / 3`。

**为什么单独列一条**：这不是能靠读代码或 `vite build` 发现的错误 ——
它是「数据用错了源」，编译期毫无征兆。同理，若某行判据是**空白**，
那是"没取到信息"的诚实降级，**可以接受**；
印着别的活动的判据才是 bug。

**失败长什么样**：多行判据长得一样 → 前端又在无条件取某一条活动的数据。
### 3.2 逐条点结果

**输入**（严格照这个填）：

| 行 | 点这个按钮 | 再点 |
|---|---|---|
| 第 1 行（当天第一条） | **不配合**（红色） | 不用再点 —— 选了这个，提示阶梯和步数**应该自动消失** |
| 第 2 行 | **跳过**（灰色） | 不用点 |
| 第 3 行 | **跳过**（灰色） | 不用点 |

**预期**：
- 第 1 行选了「不配合」后，**「用到第几级提示？」和「做到第几步」两个问题都消失**。
  留着就是 bug —— 选填「跳过/不配合」时这两个字段是纯噪音，后端拿到一对矛盾答案。
- 第 2、3 行同理，两个问题都不出现。

### 3.3 ★ 核心断言：其他观察框不计入抗拒

**输入**：在「**补充一句（选填）**」对应的「其他观察」框里填：

```
今天在超市他蹲下来捂住耳朵了，我没理他，过了一会儿自己好了。
```

**操作**：点「**提交今天的反馈**」。

**预期**（这一屏是整个 demo 的核心，务必核对）：

1. 出现「反馈处理结果」，其中一行加粗显示：
   ```
   ★ refusal_counts = {"<第1行的活动id>": 1}
   ```
   **必须是 `{"<第1行id>": 1}` —— 只有第 1 行有值，第 2、3 行必须是 0。**

   这是**最容易验错的一点**。改动前这三者都会各记至少 1 次抗拒，
   因为系统会拿「当天计划的全集」做「事件 × 活动」的笛卡尔积匹配 ——
   家长明明只填了第 1 行，另两行却白得抗拒记录。逐条填之后不可能再发生。

2. **`落库 observations 0 条`**，`本次调模型 0 次`，耗时约 100ms。

   > ⚠️ **离线模式下 observations 恒为 0，这是正确输出。**
   > 事件抽取要调模型，而降级模式的规矩是「一条都不编」
   > —— 不假装"今天成功了"来凑满链路（PROGRESS 阶段 3 的坑 7）。
   > 所以这条断言**不是靠"观察框没写进数据"侥幸通过的**，
   > 它验证的是归属逻辑本身：3 条 session 都真实落库了
   > （第 1 条 refused / 第 2 条 skipped / 第 3 条 skipped），
   > 而抗拒只落在家长亲手填「不配合」的那一条上。
   >
   > 想看到 observations 真有内容，必须关掉离线模式走真实模型（慢）。

3. 下方自动出现「状态转移」和「日结」两块 —— **不需要点第二个按钮**。
   日结里能看到当天练过的能区方向（离线模式只报计数事实）。

**失败长什么样**：`refusal_counts` 里有 2-3 个 key → 归属逻辑坏了（迁移最该盯的回归点）。

## 第 4 步：★ 并发 —— 换 PostgreSQL 换来的东西

**操作**：
1. 切到「**进度**」标签页（进度/日结现在在单独一页）
2. F12 → Network 面板，勾上 **Preserve log**
3. 反复在「今天」和「进度」之间来回切，看 Network

**预期**：
- 进「进度」页时 `GET /api/progress/demo-001` 和 `GET /api/summaries/demo-001`
  **同时发出、几乎同时返回 200**
- Console **没有红色报错**，「状态机与日结」区正常显示内容

> **为什么这一条重要**：`ProgressView` 组件内部就是用
> `Promise.all([api.progress(), api.summaries()])` 并发发这两个请求。
> 迁移到 sqlite 之前，**这正是偶发 500 的地方** ——
> 实测 15 轮 × 12 并发 = 180 个请求失败 8 个，而串行连打 15 次全绿
> （sqlite3 的游标不是线程安全的，`check_same_thread=False` 不等于线程安全）。
>
> 换 PostgreSQL 后同样形状实测 **180 请求 0 失败**。
>
> ⚠️ **只进一次「进度」页不算数** —— 要来回切 8-10 次，
> 每次都确认 Network 里两个请求时间戳挨着、都是 200。

## 出了问题怎么定位

| 现象 | 先查 |
|---|---|
| 页面全空 / 全 404 | vite 代理端口没改到 8123，打到别人服务上了 |
| 每次进「今天」都等很久 | 缓存没生效 —— 确认 `/api/card` 里有 `store.latest_plan` 那一步 |
| 改了「每天可用时间」但安排没变 | 画像变了但缓存没比对 `profile_id`，检查 `/api/card` 的失效分支 |
| 前端一直转圈 | 后端没起，或 `ASD_NO_LLM` 没加（真调模型要 30-45s） |
| Network 里 500 | 看后端终端的 traceback；并发相关先看是不是还在用旧的 sqlite 路径 |
| `refusal_counts` 有多个 key | 反馈归属逻辑回归 —— 对照 `feedback.apply_feedbacks` |
| 红旗为空 | 样本报告里的「咬自己的袖子」被改过，或红旗规则没接上 |
| 看不到「能力画像」卡片 | `/api/state` 没返回 `assessments`，或前端没接 `ProfileView` |
| 数据重启后没了 | PG 容器没挂 volume，见 0.1 的 `-v ganyu_pgdata:...` |

**兜底**：前端整个砍掉也能交 —— `loop.py --no-llm --script hardcoded`
（0.4s，五日闭环 + 冷却 + 日结落库，已实测全绿）覆盖全部技术叙事。
