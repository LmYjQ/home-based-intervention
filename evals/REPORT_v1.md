## 4. 重排为什么没开

重排（`BAAI/bge-reranker-v2-m3`）要把**书里的片段**发给外部 API。
评测要跑 27 条 × 20 个候选 = 540 次外发，同一批内容反复上传。
本轮只验证重排接口本身可用（单独测过：相关性 0.959 vs 0.001，排序合理；
两条降级路径也验过：没 API key、配置关闭时都正确回退并说明原因）。

**重排的实际收益要用 `--rerank` 单独测**，测的时候要注意外发量。
计划 §9.2 验收要求"关闭 reranker 时仍有可接受的召回"——
本轮 Recall@5 = 88% 就是这条的答案：**关掉也达标**。

## 5. 测出来的五个问题（本轮未修）

### 5.1 硬凑率 100% —— 向量路没有相似度下限

**现象**：问"红烧肉怎么做才好吃"，返回了 5 条书里的段落。

**根因**：向量检索**永远能返回"最像的"若干条**，哪怕完全不相关。
`ts_rank_cd` 有天然下限（不匹配就是 0），向量路没有。
实测最近邻余弦距离：

| 查询 | 类型 | 最近邻距离 |
|---|---|---|
| 共同注意是什么概念 | 相关 | 0.3753 |
| 引导式参与到底是什么意思 | 相关 | 0.3970 |
| 孩子发脾气摔东西尖叫 | 相关 | 0.4463 |
| How do I teach English grammar | **无关** | 0.4619 |
| 红烧肉怎么做才好吃 | 无关 | 0.5345 |
| 明天上海天气怎么样 | 无关 | 0.5610 |
| 今天上证指数涨了多少 | 无关 | 0.5716 |

0.50 落在相关与无关之间，**但单看距离不够**：
英文问句（English grammar）落在 0.46，因为同语言让距离天然偏低。
所以还需要关键词路配合（关键词路 0 条 + 距离超阈值 → 判无关）。

**候选修法**（未实施）：向量距离上限约 0.50，
加上"两路皆空则判无关"。阈值需要重新标定 ——
上表只有 7 个查询点，样本太少。

**为什么这轮不做**：改动会直接影响召回行为，
而本轮的目的是先量出基线。阈值定多少该由 2B 后续调参决定，
不能拍脑袋。

### 5.2 三条 MISS 是排序问题，不是召回问题

`sensory_sensitive` / `what_is_asd` / `emotional_regulation` 三条未命中，
但**两路各召回了 30 条**——内容在库里，只是没排进前 5。

共同特征：排在前面的**全是 `013_readiness` 章节**。
那个章节讲"家长焦虑 → 反馈循环 → 更焦虑"，跟问题表面沾边
（焦虑、压力、调节、准备），语义上却不是答案。

例（`emotional_regulation`，查询"孩子情绪调节不好，一点事就崩溃"）：

```
1. p209 [013_readiness] My whole life seems to revolve around keeping him happy by not rocking...
2. p218 [013_readiness] Modifying the Contract With Yourself: Expecting to Bat .300...
3. p229 [013_readiness] he impact of medical conditions, so that the child can more readily take...
```

期望的 `010_the_breaking_point`（崩溃点）一章在 top-5 里没有。

**这是重排最该发力的地方** —— 重排能看出"这段到底在讲什么"，
而 RRF 只看名次。这大概也是 §4 里重排该单独测的原因。

### 5.3 参考文献章节被当成证据返回

**现象**：查"共同注意是什么概念"，返回的前 8 条证据里有 **4 条**来自
`References By Author`（p353-354、p338-339）和 `References by Chapter`（p326-328）。

**根因**：参考文献块的 `knowledge_type` 已经正确标成 `'reference'`
（References By Author 73 块、References by Chapter 79 块），
**信息是有的，检索侧没用**。`search.py` 的过滤只看 `review_status`。

**为什么这是问题**：给家长的证据应该是"书里怎么讲的"，
不是一串参考文献条目。引用章节也是 `rights_status` 允许的，
但它**不构成对家长有用的建议依据**。

**候选修法**（未实施）：召回阶段排除 `knowledge_type='reference'`，
或者在证据组装阶段降权并标注"这是文献引用，不是书中论述"。

### 5.4 术语表有重复项，桥接会命中两次

**现象**：库里 `concept_id='consultant'` 和 `'rdi_consultant'` 两条的
`canonical_name_en` 都是 "RDI consultant"。

**后果**：查"顾问"时两个 concept_id 都会被桥接命中，
`keyword_query` 里 "RDI consultant" 出现两次，概念 ID 列表也重复。

**为什么会有**：历史上手工加进库的 `consultant` 没能进 `CORE_CONCEPTS`，
而 `concepts.load()` 原来只按 `concept_id` 删旧写新，不处理"规范名相同"的情况。

**候选修法**（未实施）：`load()` 清理时按 `canonical_name_en` 合并重复，
保留 `concept_id` 字典序小的那个。

### 5.5 必含术语命中率只有 56%

术语命中率低的两类原因：

1. **标注用的是正文里的主题词，结果命中的是叙事段落**。
   比如"感觉敏感"期望命中 `sensory`，但 top-5 的片段开头是
   "tive feedback loop, where parental anxiety triggers more stress"，
   术语在片段的后半段被截断了。
2. **桥接不精准**：`sensory_sensitive` 这条桥到了
   `sensory integration`（感统），但书里主要讲的是神经系统与 co-regulation，
   不是感统疗法 —— 概念表里那条 `limitations` 写的就是这个警告。

第 1 类**部分是度量问题**：片段截断 130 字符做词匹配，
长片段的术语在后面就看不到了。可以改成匹配父块全文（评测口径问题，不是检索问题）。

## 6. 这份报告说明了什么（关于"要不要上框架"）

`docs/RAG_自建vs框架_逐项对照.md` §7 写着：

> **2B 的评测结果会直接检验这份文档的每一条结论。**
> 评测集是这份文档的证伪机制，不是它的注脚。

本轮的实际结果：

| 文档的结论 | 本轮证据 |
|---|---|
| 自建 RRF + Postgres FTS 够用 | **支持**。关掉重排，Recall@5 = 88%，达标 |
| 中文查询靠 bge-m3 + 术语桥接 | **部分支持**。桥接命中率 19/27，桥不到时关键词路为 0 |
| 框架的 BM25 会更好 | **不适用**。关键词路从未单独命中过，换 BM25 改不了这个 |
| 页码可定位是自建的优势 | **支持**。100%，且每条证据都带章节 + 页码 + `relevance_reason` |
| 框架没有"不硬凑"的概念 | **反过来印证**。自建这边也漏了，得自己加距离阈值 |

**最后一行值得展开**：文档说框架缺"人工审核状态过滤"这类概念，
所以我们自建了。**但"无关问题不硬凑"这个概念，自建这边同样漏了** ——
而且是在评测把它量出来之后才意识到。
这不是"自建更好"的证据，是"**两种方案都得自己保证质量**"的证据。
