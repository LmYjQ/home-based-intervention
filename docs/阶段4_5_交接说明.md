# 阶段 4（反馈迭代）+ 阶段 5（持久化与调试）交接

> 2026-10-26。对应计划 §11 / §12。测试：`pytest -q` 317 passed。

## 1. 阶段 4 的图

```text
capture_feedback                 写 feedback；首次提交才更新 trial 执行状态
  → load_feedback_context        方案正文/版本、child_context、记忆、历史尝试
  → analyze_feedback             带历史对比；结果立即写 analysis_json
  → next_step                    continue / adjust / followup / stop
       ├─ continue / stop / 追问用尽 → extract_memories → finalize_feedback
       ├─ followup → generate_feedback_followup → await_feedback_answer (interrupt)
       │                              → analyze_feedback（最多 1 轮）
       └─ adjust → prepare_feedback_retrieval → rewrite → retrieve → rerank
                    → persist_evidence_bundle → evidence_gate
                    → build_feedback_adjustment → safety_review → render_answer
                    → extract_memories → finalize_feedback
```

### 两个设计决定

1. **adjust 只出文字，不出新卡、不建 trial**。反馈迭代调整的是正在执行的那一条；
   再给 2–3 张新卡会让家长不知道该继续哪条。
2. **执行状态和"已分析"分开**：
   - `trials.status`：`accepted → attempted / not_attempted / stopped`
   - `feedbacks.completed_at`：这次反馈处理完（重试直接读缓存）
   不拿 `reviewed` 覆盖执行状态，否则"没做"这个信息会丢。

### 数据

- 迁移 008：`feedbacks` 加 `stopped / analysis_json / next_step_json /
  followup_answers_json / result_json / followup_rounds / analyzed_at / completed_at`
- 迁移 009：`trials.plan_version`（从 `plans.plan_version` 回填）

### API

| 方法 | 路径 | 作用 |
|---|---|---|
| POST | `/api/trials/{id}/feedback` | 提交反馈；命中缓存/中断时直接返回 |
| POST | `/api/trials/{id}/feedback/resume` | 回答反馈追问 |
| GET | `/api/trials/{id}/feedback/{turn_id}` | 刷新页面恢复结果 |

`turn_id` 同时是幂等键和 checkpoint 线程的一部分
（`feedback-{trial_id}-{turn_id}`），重试必须用同一个。

## 2. 阶段 5 的调试

### API

| 方法 | 路径 | 作用 |
|---|---|---|
| GET | `/api/debug/conversations/{id}/state` | 当前 state 摘要（脱敏） |
| GET | `/api/debug/conversations/{id}/checkpoints` | checkpoint 历史 |
| POST | `/api/debug/conversations/{id}/fork` | 从历史 checkpoint 派生独立分支 |

### 分叉配方

```python
source = await graph.aget_state({thread_id: 源, checkpoint_id: 选中})
parent = await graph.aget_state(source.parent_config)
producer = parent.next[0]                      # 产生该 checkpoint 的节点
await graph.aupdate_state({thread_id: 新线程}, source.values + patch, as_node=producer)
await graph.ainvoke(None, {thread_id: 新线程})
```

- 源线程 head / 历史不变；
- 目标线程 `debug=True`，写节点会跳过业务表并记 `writes_skipped`；
- **不要用 `acopy_thread()`**：当前 `AsyncPostgresSaver` 未实现；
- 这是合成种子 checkpoint，不是逐字节复制整条历史链。

### 顺手修的 bug

`runtime.shutdown_graph()` 之前先清空全局再判断 `_saver_ctx`，
条件永远为假，saver 从来没关过。重启测试会因此挂连接。
